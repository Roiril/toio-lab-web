## 2. Arduino IDE の基本を理解する

あとで迷わないように用語を押さえておきます。

- **スケッチ (`.ino`)**: マイコンに書き込むプログラムのソースコード。
- **コンパイル (検証)**: ソースコードを ESP32 が理解できるバイナリに変換する作業。ボタンは左上の ✓ マーク。
- **書き込み (アップロード)**: コンパイル後のバイナリを ESP32 の Flash メモリに転送する作業。ボタンは → マーク。**内部的にはコンパイル→書き込みの連続実行**なので、通常は「書き込み」ボタンを押すだけで OK。
- **シリアルモニタ**: ESP32 が出力するログを PC で見るためのウィンドウ。右上の虫眼鏡アイコン。
- **ボード / ポート**: どのマイコンと、どの USB ポート経由で通信するか。書き込み前に必ず選択する。

> **書き込みが済んだコードは ESP32 の電源を切っても消えません。** 一度書けばプログラムは残り続け、電源再投入すると自動で `setup()` → `loop()` が走ります。

## 3. 初回セットアップ (1回だけやる作業)

### 3-1. Arduino IDE をインストール
https://www.arduino.cc/en/software から 2.x 系をインストール。

### 3-2. ESP32 ボード定義を追加
1. `ファイル` → `基本設定`
2. `追加のボードマネージャの URL` に以下を追加
   ```
   https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
   ```
3. `ツール` → `ボード` → `ボードマネージャ` を開き、「esp32」で検索して **esp32 by Espressif Systems** をインストール (3.x 系推奨)。

### 3-3. ボードを選択
`ツール` → `ボード` → `esp32` → **`XIAO_ESP32S3`** を選択。

### 3-4. PSRAM を有効にする (重要)
`ツール` メニューで以下を確認:
- **PSRAM**: `OPI PSRAM`
- **Flash Size**: `8MB (64Mb)`
- **Partition Scheme**: `Default 4MB with spiffs` 以上

> PSRAM を無効にするとカメラ初期化が失敗します。

### 3-5. ドライバ (Windows のみ)
XIAO ESP32S3 は通常ドライバ不要ですが、デバイスマネージャに認識されない場合は CH340/CP210x ドライバを追加で入れてください。

## 4. 書き込み手順 (毎回の作業)

### 4-1. スケッチを開く
Arduino IDE で [esp32s3-cam.ino](esp32s3-cam.ino) をダブルクリック、または `ファイル` → `開く` から選択。

### 4-2. WiFi 情報を書き換える
スケッチ先頭の以下 2 行を自分の環境に合わせて編集:
```cpp
const char* ssid     = "YOUR_SSID";
const char* password = "YOUR_PASSWORD";
```
**必ず 2.4GHz の SSID** を指定すること。スマホテザリングの場合、「2.4GHz のみ」に設定しておくと確実。

### 4-3. USB で接続してポートを選ぶ
1. USB-C ケーブルで PC と接続。
2. `ツール` → `ポート` から新しく現れた COM ポート (Windows) / `/dev/cu.usbmodem*` (Mac) を選択。

### 4-4. 書き込み (→ ボタン)
`スケッチ` → `マイコンボードに書き込む` (または Ctrl+U / 右矢印アイコン)。

- 初回書き込み時のみ「BOOT ボタンを押しながら RESET」が必要になる場合があります (最近の XIAO ESP32S3 は通常不要)。
- 書き込みに失敗したら、USB ケーブルを抜き差し → ポート再選択 → もう一度書き込み。
- 書き込み中はシリアルモニタを閉じておくこと (COM ポートを取り合うため)。

### 4-5. 書き込み完了サインを確認
下部ウィンドウに `Hard resetting via RTS pin...` や `Leaving...` が出れば成功。

## 5. 動作確認

### 5-1. シリアルモニタを開く
1. `ツール` → `シリアルモニタ` (Ctrl+Shift+M)
2. 右下のボーレートを **115200 bps** に合わせる。
3. ESP32 の RESET ボタンを一度押すか、USB を抜き差しする。

### 5-2. 期待されるログ
```
=== XIAO ESP32S3 Camera ===
Camera OK
WiFi接続中..........
接続完了! IPアドレス: 192.168.x.x
HTTPサーバー起動
>>> ブラウザで開く: http://192.168.x.x/
>>> WebアプリのカメラURL: http://192.168.x.x
```
この **IP アドレスをメモ**してください。

### 5-3. PC のブラウザから動作確認
上で表示された URL (`http://192.168.x.x/`) を PC のブラウザで開く。
- 真っ黒なページに映像が流れれば成功。
- `/status` にアクセスすると `{"status":"ok","camera":"OV2640","ip":"..."}` が返る。
- `/capture` にアクセスすると JPEG 画像が 1 枚表示される。

> ⚠️ **動作確認が終わったら、このタブは必ず閉じること。**
> トップページ (`/`) は `<img src='/stream'>` で MJPEG ストリームを張りっぱなしにします。ESP32 のサーバは **シングルスレッド** なので、このタブが開いている間は他のリクエスト (`/status`・`/capture`) が全てブロックされ、**Web アプリから接続できなくなります**。
> 単発で確認したいだけなら `http://192.168.x.x/status` や `http://192.168.x.x/capture` を直接開くほうが安全です。

## 6. Web アプリ側の設定

1. toio-lab-web を開く。
2. 右上の歯車アイコン → 設定モーダルを開く。
3. 「Camera URL (ESP32S3)」に **`http://192.168.x.x`** を入力 (末尾スラッシュなし、ポート番号なし)。
4. `保存` を押す。保存と同時に接続チェックが走り、成功すれば Camera パネルの点灯が緑になります。
5. `Connect` ボタンで再チェック、`Preview` で映像表示、📷 ボタンで LLM に画像添付。

> **重要 — Mixed Content**: toio-lab-web を `https://` で開いていると、ブラウザが `http://` の ESP32 へのアクセスをブロックします。必ず `http://localhost:xxx` または `file://` で開くこと。
>
> **重要 — ESP32 直アクセスのタブを残さない**: 動作確認で `http://192.168.x.x/` を開いたタブが残っていると、ストリームで ESP32 が占有され Web アプリの `Connect` が必ず失敗します。必ず閉じてから Web アプリ側で接続してください。

## 7. 再接続・電源を入れ直したとき

修正後のスケッチは **WiFi 自動再接続** を有効にしているので、以下の状況で基本放っておけば復帰します。

| 状況 | 挙動 |
| --- | --- |
| ESP32 の電源を入れ直した | 書き込み済みコードが自動起動 → WiFi に自動接続 → サーバ起動 |
| WiFi が一時的に切れた | 5 秒ごとに `WiFi.reconnect()` を試行 (loop 内で監視) |
| ルーターを再起動した | 上記同様、復旧後に自動で再接続 |
| PC 側で URL をもう一度入力したい | アプリの設定モーダルで同じ IP を再保存 (または `Connect` ボタン) |

### IP アドレスが変わったときは？
- DHCP の仕様上、長時間電源を切ると IP が変わることがあります。
- **シリアルモニタを再度開いて新しい IP を確認** → アプリ側で URL 更新、が最短ルート。
- 変わらないようにするには、ルーター側で DHCP 予約 (MAC アドレス固定 IP) を設定するのが確実。

### 再接続にコンパイルは必要？
**不要です。** 書き込み済みのコードは Flash に残っています。電源 ON で自動的に動き出します。

## 8. トラブルシューティング

### A. シリアルモニタで「WiFi接続失敗」と出る
- SSID / パスワードのタイプミスを再確認。
- 5GHz 専用 AP に繋ごうとしていないか確認。
- スマホテザリングなら、機内モード ON/OFF で一度リセットしてみる。
- 修正したらスケッチを **再コンパイル&書き込み** (WiFi 情報はコードに埋め込まれているため)。

### B. ブラウザで `http://192.168.x.x/` が開かない
- PC と ESP32 が **同じ WiFi ネットワーク** に繋がっているか確認。
- `ping 192.168.x.x` が通るか試す。
- ルーターが「アクセスポイント分離 (AP Isolation)」を有効にしていないか確認。

### C. toio-lab-web のカメラ欄が Disconnected から変わらない
まず **`http://<ESP32のIP>/` を表示しているブラウザタブが残っていないか確認**。残っていれば閉じる (最頻出の原因)。それでもダメなら:

1. ブラウザの開発者ツール (F12) → Console タブを開く。
2. `Mixed Content` エラー: アプリを `https://` で開いている。`http://localhost` で開き直す。
3. `Failed to fetch` / `CORS error`: ESP32 側のエラー。シリアルモニタで動いているか確認。
4. `AbortError` / タイムアウト: WiFi の電波が弱い可能性、または上記のストリーム占有タブが残っている。ESP32 を近くに置く + タブを閉じる。
5. 検証コマンド: 新しいタブで `http://<ESP32のIP>/status` を開き JSON が返るか確認 (返らなければ ESP32 側の問題)。

### D. Camera init failed: 0x... と出る
- PSRAM が `OPI PSRAM` になっていないと高確率で発生。ツールメニューを再確認。
- カメラモジュールのフレキケーブルが浮いていないか物理確認。
- 上記修正してから **再コンパイル&書き込み**。

### E. 書き込みに失敗する / COM ポートが見えない
- 充電専用ケーブルではないか確認 (太い・短いケーブルが安定)。
- USB ハブ経由だと電力不足になることあり。PC に直挿しで試す。
- `ツール` → `ポート` がグレーアウトしている場合、ドライバ不足。
- それでもダメなら BOOT ボタン押しながら RESET → ポートが現れたら書き込み。

### F. 画像は出るが壊れている / たまに接続が切れる
- 修正済みの `handleCapture` で `send_P` → `client.write` に変更済み。もし古いバージョンを書いてしまった場合は **本リポジトリの最新 `.ino` を再書き込み**。
- 被写体との距離・光量が極端な場合、`config.jpeg_quality` を 10 から 12〜15 に上げて再書き込みすると安定することがあります。

## 9. FAQ: コンパイルっていつ・何回やるの？

### Q. コンパイルは毎回必要？
**コードを 1 文字でも変えたら必要。** 書き込みボタンを押すと自動的にコンパイル→書き込みが連続実行されるので、「書き込みボタンを押す = コンパイルも走る」で OK。

### Q. 何回もコンパイル・書き込みしていい？ ESP32 が壊れない？
**全く問題ありません。** ESP32 の Flash は約 10 万回の書き換え寿命があるので、開発中に毎日何十回書いても数年は余裕。

### Q. コンパイルに失敗した。もう一度コンパイルすべき？
原因を直してから書き込みボタンを押せば、改めてコンパイル→書き込みが走ります。**部分コンパイルのキャッシュは有効**なので、2 回目以降は速くなります。

### Q. 書き込みは成功したけど動かない。どうする？
`.ino` を書き換えていないなら再コンパイルは不要。
- RESET ボタンを押す
- USB を抜き差し
- シリアルモニタでログを見る

これで原因が分かることが多いです。コードを修正した場合だけ、もう一度書き込み (=自動で再コンパイル) を実行してください。

### Q. WiFi の SSID / パスワードだけ変えたい。再コンパイル必要？
**必要です。** WiFi 情報はソースコードに埋め込まれているため、書き換えたら再書き込み (=再コンパイル) が必要。
(将来的に WiFiManager を導入してブラウザから設定できるようにする拡張も可能)

### Q. 書き込み後、Arduino IDE を閉じてもいい？
**OK です。** ESP32 のプログラムは Flash に書き込まれているので PC から切り離しても動き続けます。シリアルモニタでログを見たいときだけ Arduino IDE を起動すれば十分。

# 自己改善ワークフロー (Self-Improvement Workflow)

このワークフローは、機能実装、リサーチ、エラー修正などのタスクが完了した後に実行し、将来の作業効率を上げるためにエージェントのルールやワークフローを自己改善することを目的とします。

## 1. 振り返りと課題の抽出
- 現在の会話ログ全体を振り返り、以下の点を抽出してください。
  - エラーが頻発した箇所
  - 作業効率が落ちた（詰まった）原因
  - ユーザーからの指摘や修正指示が多かった部分
  - エージェントの設定や前提知識（ルール、ワークフロー）の不足・不一致

## 2. 対象ドキュメントの特定と確認
- 抽出した課題に基づき、改善すべき対象のドキュメントを特定してください。対象は主に以下のディレクトリ内に限定されます。
  - `.agent/rules/`
  - `.agent/workflows/`
- 該当するドキュメントが存在する場合は、必ず `view_file` またはディレクトリ検索のツール（`list_dir`等）を使用して現在のファイルや内容を確認してください。新しいファイルの追加が必要な場合は新規作成を検討してください。

## 3. 改善案の作成（差分ベース）
- 対象ファイルに対する改善案を作成します。
- markdownのdiffブロックなどを使用して、**既存の内容からの差分（変更箇所のみ）**がユーザーに明確に伝わるように提示してください。
- その際、どのような目的で、なぜその変更を行うのかを、装飾を省いて客観的かつ簡潔に説明してください（ルール `communication.md` 準拠）。

## 4. ユーザーの承認と反映
- 提案した改善案（差分と理由）をユーザーに提示し、事前承認を求めてください。
- ユーザーから「進めて」「許可」「OK」などの明確な承認を得るまでは、ファイルの書き換えを実行しないでください。
- 承認が得られたら、`multi_replace_file_content` などのツールを使用して、該当ファイルに変更を反映させてください。

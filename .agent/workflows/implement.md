# 実装ワークフロー (Plan-Code-Evaluate)

タスクを受領した場合、以下のフェーズに沿って進行してください。

## 1. Plan (計画)
- 要求を分析し、変更が必要なファイルと具体的な修正方針をリストアップする。
- `.agent/plans/YYYY-MM-DD_<slug>.md` に計画ファイルを作成する（`status: in-progress`）。
- `.agent/tasks/YYYY-MM-DD_<slug>.md` に対応するタスクチェックリストを作成する。
- ユーザーに計画を提示し、承認を得る。

## 2. Code (実装)
- 承認された計画に基づき、該当ファイルへの書き込みを実行する。
- `.agent/tasks/` のチェックリストを随時更新する（`[/]` → `[x]`）。

## 3. Evaluate (検証・客観的センサー)
- 変更後、構文エラーがないかツールで確認する（可能であれば）。
- ユーザーに対し「ブラウザのリロードと動作確認をお願いします。コンソールにエラーが出た場合は、そのエラー文言をそのまま貼り付けてください」と依頼する。
- エラーが報告された場合は、主観的な推測を避け、エラー文言を元に「Plan」フェーズに戻る。

## 4. Record (記録)
- 計画ファイルを `status: done` に更新する。
- 重要な設計判断があれば `.agent/memory/decisions.md` に追記する。
- 新たなバグや制約を発見した場合は `.agent/memory/known-issues.md` に追記する。
- アーキテクチャに変更があれば `.agent/memory/architecture.md` を更新する。

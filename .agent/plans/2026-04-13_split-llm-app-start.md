# LLMとアプリの分離（LAN内別PC実行機能）の設計計画

現在の `start.ps1` と `start.bat` はローカルPCでLLM(Ollama)とWebアプリ(npx serve)の両方を立ち上げる構成ですが、これをLLM用PCとアプリ(toio接続)用PCの2つに分離します。

## 背景と目的
1. **負荷分散**: 重いLLMの処理を専用のパワフルなPC（PC A）で実行し、toioとのBluetooth接続等を行う身軽なPC（PC B）からLAN経由でそこにアクセスできるようにする。
2. **ユーザビリティ**: 起動時に接続確認が行われ、失敗した場合はユーザーに対処法を提示して親切に案内する。

## 変更内容詳細

### 1. `start-llm.ps1` / `start-llm.bat` (新規作成)
LLM（Ollama）を動かすPCで実行するスクリプトです。
- **処理フロー**:
  1. Ollamaのインストールとアップデート確認。
  2. 環境変数 `OLLAMA_HOST=0.0.0.0` と `OLLAMA_ORIGINS="*"` を設定し、LAN内の他のPCからOllamaへアクセスできるようにします。
  3. Ollamaサーバーを起動。
  4. 必要なモデル（例: `gemma4:e4b`）をダウンロード。
  5. **ユーザー自身のIPアドレス（IPv4）を画面にデカデカと表示**し、「アプリ側PC（PC B）でこのIPアドレスを入力してください」と案内します。

### 2. `start-app.ps1` / `start-app.bat` (新規作成)
WebアプリとtoioのBluetooth接続を動かすPCで実行するスクリプトです。
- **処理フロー**:
  1. ユーザーに対して「LLM PCのIPアドレス」の入力を求めます。（デフォルトは `localhost` とし、同PCで動かす場合にも対応できるようにします）。
  2. 入力されたIPに対して、PowerShellの `Invoke-RestMethod` などを用いて `http://<IP>:11434/api/tags` をテストコールし、アクセス可能か確認します。
  3. **接続不能な場合**: 警告メッセージ（ファイヤーウォールの確認やLLM PC側の起動完了待ちなど）を表示して一時停止（Pause）します。
  4. **接続成功の場合**: 
     - 取得したURLをフロントエンド（JS）で読み込めるように、一時ファイル `js/config.js`（または `.env.js` 的なもの） を生成してURLを書き込みます。
     - `npx serve .` でWebサーバーを起動し、完了とします。

### 3. フロントエンドの修正 (`index.html`, `js/app.js`)
- `index.html` に `<script src="js/config.js"></script>` を追加し、起動時に自動設定されたURLを読み込みます。
- `js/app.js` では初期値として `window.APP_CONFIG.OLLAMA_URL` を参照し、動的にUIの「設定 > Ollama URL」や `OllamaClient` の初期化へ反映させます。

### 4. 既存スクリプトの整理
- 既存の `start.ps1` と `start.bat` は不要になるため削除するか、互換性のために「どちらかを起動するランチャー」に変更するか、バックアップとして `_old` フォルダ等に退避します。（標準としては削除し、READMEで新しい手順を説明します）

## User Review Required

> [!IMPORTANT]
> 以下の点についてユーザーの確認が必要です。
> 1. **既存の `start.ps1`/`start.bat` の扱い**: この2つは削除してしまってよいでしょうか？（それとも、これらを残して「1. LLMを起動 2. アプリを起動」を選べるメニューにする方がよいでしょうか？）
> 2. **LAN内のファイアウォール設定**: Windowsのファイアウォールでポート11434がブロックされる可能性が高いです。必要であれば `start-llm.ps1` の中で自動的にファイアウォールの穴開け（許可ルール追加）を実行する処理を入れてもよいでしょうか？（管理者権限が必要です）
> 3. **IP自動探索の有無**: App側の起動時に、手入力だけでなく「同一LAN内の11434ポートを持つIPを自動探索する」機能を付与することも可能ですが、探索に数十秒かかることがあるため、今回は**ユーザーがIPを手入力する前提**で設計していますがよろしいでしょうか？

## Verification Plan
1. ローカルマシン上で `start-llm` と `start-app` (IP: localhost) を両方実行して基本動作を確認します。
2. IPにダミーの到達できないものを入力し、リトライやエラー停止のUIが正しく動作するか確認します。
3. アプリ上の設定画面で、自動的に渡されたIPアドレスが初期設定されているか確認します。

# Agent Loop Refactoring: Planner-Generator-Evaluator アーキテクチャ

## 目的
toioの自律移動を制御する `AgentLoop` の構造を改善し、「Coordinator-Planner-Evaluator」から「Planner-Generator-Evaluator」の3層構造（タスクリスト駆動）へとリファクタリングする。

## 概要
ユーザーの入力に基づいて、多段階の「行動計画（タスクリスト）」を最初に作成し、その各タスクを順次実行・評価するループへと変更する。

### 各フェーズの役割
1. **Phase 1: Planner (計画の作成)**
   - ユーザー入力と現在の環境（toioの現在地など）を入力にとる。
   - 複数のステップからなるタスクリストを生成する。（JSONフォーマットの安定性を考慮し、配列だけでなくオブジェクトでラップする）。
   - 例: `{"tasks": [{"task_id": 1, "description": "X=300, Y=300に移動する"}, {"task_id": 2, "description": "その場で360度回転する"}]}`

2. **Phase 2: Generator (タスクの実行行動生成)**
   - Plannerが作成した「全体のタスクリスト」の文脈と、「現在のタスク」およびtoioの現在地を入力にとる。
   - タスクを達成するための具体的な行動（APIツール呼び出し。例：`move_to`, `rotate` など）を生成・実行する。

3. **Phase 3: Evaluator (実行結果の評価)**
   - 1回の行動実行後、toioの実際の位置や状態を確認し、「現在のタスクのdescription（自然言語）」が達成できたかを評価する。
   - 移動以外のタスク（回転など）も評価できるよう、以前の「目標座標との距離」に限定せず、汎用的な判定フォーマットを使用する。
     - 出力例: `{"success": false, "reasoning": "まだ指定の座標に到達していません"}`
   - 達成できていない場合: その理由（フィードバック）をGeneratorに渡し、同じタスクを再試行させる。
   - 達成できている場合: Generatorに完了を伝え、全体のタスク進行インデックスを1つ進める。

### イテレーション制限の変更
- `maxIterations` は「1つのタスクを達成するためにGeneratorが試行できる最大回数」として定義し直します。
- 全体の最大イテレーションではなく、個別のタスクごとにリセットされるように実装を工夫します。

## 変更対象ファイル
- `js/agent-loop.js`
  - `run()` メソッドの内部ロジックを全面改修。
  - プロンプトをCoordinator/Planner/Evaluatorから、Planner/Generator/Evaluator役割に更新。

## 検証方法
- ファイルの保存後、ブラウザをリロード。
- 「300, 300に移動して、そのあと500, 500に移動して」のような複数ステップを要求するプロンプトを送信。
- 意図通りに2段階のタスクとして認識され、順番に実行・評価されることをコンソール及びUI上のログから確認する。

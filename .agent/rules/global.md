# グローバルルール

1. **自律性と承認**: タスクは自律的に進行するが、計画段階およびファイル書き込みの直前には必ず日本語で概要を説明し、ユーザーの明確な承認（「OK」「進めて」等）を得ること。
2. **プロセス順守**: 機能実装時は必ず `implement.md` ワークフロー（Plan -> Code -> Evaluate）に従うこと。
3. **客観性の維持**: コードの実行結果やエラーの評価は主観で行わず、ブラウザのコンソールエラー、リンター出力、OllamaのAPIレスポンスステータスなどの客観的なデータに基づき判断すること。
4. **出力制限**: 明示的な指示がない限り、コード全体をチャットに出力せず、変更箇所のみを簡潔に提示すること。
5. **計画の永続化**: 実装計画やタスクリストは `.agent/plans/` および `.agent/tasks/` ディレクトリに実ファイル（`YYYY-MM-DD_<slug>.md`）として作成・更新し、会話終了後も他のエージェントが参照できるようにすること。また、システム機能（`IsArtifact: true`）による保存も併用し、機能性と永続性を両立させること。
6. **知識の蓄積**: 重要な設計判断、既知の問題、アーキテクチャの変更があった場合は `.agent/memory/` 配下の該当ファイルを更新すること。
7. **Windows環境のエンコーディング遵守**:
    - **PowerShell (.ps1)**: 日本語を含む場合は、必ず「UTF-8 with BOM」形式で保存すること。BOMがない場合、古いPowerShell（5.1等）では文字化けが発生する。
    - **バッチファイル (.bat)**: 言語環境（CP932等）に依存する文字化けを防ぐため、日本語を含めず、**常に ASCII 文字のみ**で作成すること。メッセージ表示が必要な場合は PowerShell スクリプトに委譲する。
8. **スクリプト作成時の変数展開防止**: `$` を含む PowerShell スクリプト等を生成する際は、シェルによる予期せぬ変数展開（例: `$_` が空になる等）を避けるため、`run_command` による herestring 書き込みではなく、`write_to_file` などの直接書き込みツールを使用すること。
